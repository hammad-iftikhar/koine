# Koine Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Production images, a self-hosted multi-node LiveKit, environment validation that fails the boot loudly, scheduled work that runs once across N instances, and the three numbers worth watching.

**Architecture:** Six units — web on a CDN, API and agent as containers, Postgres behind PgBouncer, Redis, and LiveKit on its own machines. Everything scales horizontally except a single room, which lives on one SFU node and one agent worker.

**Tech Stack:** Docker multi-stage builds, LiveKit server, PgBouncer, Redis, Postgres advisory locks, GitHub Actions.

**Spec:** [`../specs/2026-09-18-koine/08-deployment.md`](../specs/2026-09-18-koine/08-deployment.md)

## Global Constraints

- **Node 22**, pnpm, TypeScript. Test-first where there is logic to test.
- **Secrets are server-side only.** The browser receives the LiveKit *URL* and nothing else.
- **Env vars are validated at boot.** A missing variable fails the process loudly, never at 3am as a confusing runtime error.
- **Nothing in process memory that must be shared.** Counters and coordination live in Redis; scheduled work is serialised with a Postgres advisory lock.
- **Migrations run once per release**, not on every container boot, and are additive within a release.
- **No audio and no transcripts are stored.** Recording is out of scope.
- Meeting codes are logged; message bodies and audio are not.

`packages/shared/src/env.ts`:

```ts
import type { z } from 'zod'

/**
 * Parse and validate environment at process start.
 *
 * Reports every problem at once — fixing one variable, restarting, and finding
 * the next is a loop nobody should be in at 3am. Never echoes a value: this
 * message ends up in logs.
 */
export function parseEnv<T extends z.ZodTypeAny>(schema: T, source: unknown): z.infer<T> {
  const result = schema.safeParse(source)
  if (result.success) return result.data

  const problems = result.error.issues.map((i) => `  ${i.path.join('.')}: ${i.message}`).join('\n')
  throw new Error(`Invalid environment:\n${problems}`)
}
```

`apps/api/src/jobs.test.ts`:

```ts
import postgres from 'postgres'
import { afterAll, expect, it, vi } from 'vitest'
import { withLeaderLock } from './jobs'

const url = process.env.DATABASE_URL ?? 'postgres://koine:koine@localhost:5432/koine'
const connections = [postgres(url, { max: 1 }), postgres(url, { max: 1 })]

afterAll(async () => {
  await Promise.all(connections.map((c) => c.end()))
})

it('runs the job for the holder', async () => {
  const run = vi.fn(async () => {})
  expect(await withLeaderLock(424242, run, connections[0])).toBe(true)
  expect(run).toHaveBeenCalledTimes(1)
})

it('skips on every other instance rather than running twice', async () => {
  // Six API instances each firing the retention job is six deletions racing.
  const order: string[] = []
  let releaseFirst: () => void = () => {}
  const firstDone = new Promise<void>((resolve) => {
    releaseFirst = resolve
  })

  const first = withLeaderLock(
    515151,
    async () => {
      order.push('first')
      await firstDone
    },
    connections[0],
  )

  await new Promise((r) => setTimeout(r, 50))
  const second = await withLeaderLock(515151, async () => order.push('second'), connections[1])

  releaseFirst()
  expect(await first).toBe(true)
  expect(second).toBe(false)
  expect(order).toEqual(['first'])
})

it('releases the lock even when the job throws', async () => {
  // A job that throws while holding the lock would block the schedule forever.
  await expect(
    withLeaderLock(626262, async () => {
      throw new Error('job failed')
    }, connections[0]),
  ).rejects.toThrow('job failed')

  expect(await withLeaderLock(626262, async () => {}, connections[1])).toBe(true)
})
```

- [ ] **Step 3: Write the implementation**

`apps/api/src/jobs.ts`:
```ts
import { lt, and, isNull, isNotNull } from 'drizzle-orm'
import type { Sql } from 'postgres'
import { db } from './db/client'
import { meeting } from './db/schema'
import { sql as defaultSql } from './db/client'

/**
 * Serialise a scheduled job across every API instance with a Postgres advisory
 * lock.
 *
 * ponytail: no leader election, no dedicated worker, no new deployable. Six
 * instances attempt the lock, one gets it, five skip. If job volume ever
 * outgrows this, the upgrade is a single-replica worker — do not start there.
 */
export async function withLeaderLock(
  key: number,
  run: () => Promise<void>,
  connection: Sql = defaultSql,
): Promise<boolean> {
  const [row] = await connection<{ locked: boolean }[]>`
    SELECT pg_try_advisory_lock(${key}) AS locked
  `
  if (!row?.locked) return false

  try {
    await run()
    return true
  } finally {
    // finally, not after: a throwing job must not hold the lock forever.
    await connection`SELECT pg_advisory_unlock(${key})`
  }
}

const IDLE_TIMEOUT_KEY = 100_001
const RETENTION_KEY = 100_002
const RETENTION_DAYS = 90

export function startJobs(): () => void {
  const idle = setInterval(async () => {
    await withLeaderLock(IDLE_TIMEOUT_KEY, async () => {
      const cutoff = new Date(Date.now() - 4 * 60 * 60 * 1000)
      await db
        .update(meeting)
        .set({ endedAt: new Date() })
        .where(and(isNull(meeting.endedAt), isNotNull(meeting.startedAt), lt(meeting.startedAt, cutoff)))
    }).catch((error) => console.error('jobs: idle timeout failed', error))
  }, 60_000)

  const retention = setInterval(async () => {
    await withLeaderLock(RETENTION_KEY, async () => {
      const cutoff = new Date(Date.now() - RETENTION_DAYS * 24 * 60 * 60 * 1000)
      // Chat contains people's words. Cascades remove participants and messages.
      await db.delete(meeting).where(and(isNotNull(meeting.endedAt), lt(meeting.endedAt, cutoff)))
    }).catch((error) => console.error('jobs: retention failed', error))
  }, 60 * 60 * 1000)

  return () => {
    clearInterval(idle)
    clearInterval(retention)
  }
}
```

Call `startJobs()` in `apps/api/src/server.ts` after `listen`.

- [ ] **Step 1: Write the production config**

`docker/livekit.prod.yaml`:

```yaml
# Production. The development config is separate and must not be used here —
# it advertises 127.0.0.1 and disables TURN.
port: 7880
bind_addresses: ['0.0.0.0']
log_level: info

rtc:
  tcp_port: 7881
  port_range_start: 50000
  port_range_end: 60000
  # Discover the public address rather than hardcoding it, so a replaced
  # instance does not advertise its predecessor's IP.
  use_external_ip: true

# Multi-node coordination. Two nodes minimum: one node is a single point of
# failure for every meeting simultaneously.
redis:
  address: ${REDIS_HOST}:6379

# Required, not optional. Participants behind restrictive NATs cannot connect
# without a relay, and they will not report it as a bug — they will just leave.
turn:
  enabled: true
  domain: ${TURN_DOMAIN}
  tls_port: 5349
  external_tls: true

keys:
  ${LIVEKIT_API_KEY}: ${LIVEKIT_API_SECRET}
```

- [ ] **Step 2: Write the runbook**

`docs/runbooks/livekit.md` covering, with exact commands for your host:

- **Draining a node before upgrade.** A restart drops that node's rooms; clients
  reconnect onto a healthy node. Drain, wait for rooms to reach zero, then upgrade.
- **The UDP check.** `nc -vzu <host> 50000` from outside your network. A host that
  only exposes HTTP will appear to work in testing and fail for real users — this
  is the single most common self-hosting failure and it produces no server-side error.
- **Key rotation.** Rotating invalidates every live token, so it is a planned
  operation during a quiet window, not routine hygiene.
- **Capacity.** Egress is the constraint, not CPU. A 25-person room is roughly
  50 Mbps in and up to ~100 Mbps out before simulcast helps. Set a rooms-per-node
  ceiling and measure against real traffic rather than trusting that estimate.

Expected: the client reconnects and lands on node B. Record the observed gap in

- [ ] **Step 1: Write the emitter**

`apps/agent/src/metrics.ts`:
```ts
/**
 * Structured JSON to stdout. Meeting codes are logged so a report can be
 * traced; message bodies, transcripts and audio are never logged.
 *
 * ponytail: console.log with a shape, not a metrics client. Every host already
 * collects stdout. Add a real client when someone needs a query this cannot answer.
 */
type Fields = Record<string, string | number | boolean>

function emit(event: string, fields: Fields): void {
  console.log(JSON.stringify({ event, at: new Date().toISOString(), ...fields }))
}

/**
 * The number the product lives or dies by. Emitted per segment so it can be
 * read as a distribution — an average hides the tail, and the tail is what
 * people notice.
 */
export function recordLatency(stage: string, ms: number, roomCode: string): void {
  emit('translation.latency', { stage, ms, roomCode })
}

export function recordSpend(roomCode: string, units: number, lang: string): void {
  emit('translation.spend', { roomCode, units, lang })
}

export function recordError(scope: string, error: unknown, roomCode: string): void {
  emit('error', {
    scope,
    roomCode,
    message: error instanceof Error ? error.message : String(error),
  })
}

export function recordWorkerHealth(rooms: number, channels: number): void {
  emit('agent.health', { rooms, channels })
}
```

- [ ] **Step 2: Instrument the pipeline**

In `apps/agent/src/transcriber.ts`, wrap the transcribe and translate calls with

`recordLatency('translate', …)`. In `synthesizer.ts`, record `tts_first_byte` and

- [ ] **Step 1: Write the workflow**

`.github/workflows/release.yml`:
```yaml
name: release

on:
  push:
    tags: ['v*']

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build images
        run: |
          docker build -f docker/Dockerfile.api   -t koine-api:${{ github.ref_name }} .
          docker build -f docker/Dockerfile.agent -t koine-agent:${{ github.ref_name }} .

      # Once per release, before the new API starts — not on every container
      # boot, which would race N replicas against the same migration.
      - name: Run migrations
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
        run: pnpm --filter @koine/api db:migrate

      - name: Deploy
        run: echo "Push images and restart services for your host here"
```

Rollback is redeploying the previous image, so **migrations must be additive
within a release**. A destructive migration needs its own deliberate plan and
does not belong in a normal deploy.

## Carried forward

**Retention needs a delete path before real users.** The scheduled job removes
meetings older than 90 days, but there is no per-user deletion request path. Chat
contains people's words; that is a real obligation, and it is not in this plan.
